BaseWork: конфигурация OIDC-провайдера

Дополнение 27.10.2026: локальный patch UI, профиля публикации и операторских
команд описан в docs/BASEWORK_PUBLIC.txt. Ниже сохранено описание предыдущего
этапа provider; фраза «UI не менялся» относится к тому этапу.

Статус: локальная реализация. Подключение сервера/Authelia, рабочие привязки,
commit/push и выкладка требуют отдельных поручений. OIDC по умолчанию disabled.
Новые зависимости и миграции для режима provider не нужны.

Режимы
- BASEWORK_OIDC_MODE=disabled: вход OIDC выключен; файлы OIDC не читаются.
- isolated: прежние фиксированные HTTPS-адреса и обязательный маркер локального
  стенда. Это не режим для подключения Authelia.
- provider: конфигурация из явно указанного файла
  BASEWORK_OIDC_CONFIG_FILE=/run/config/basework_oidc.json.
  Файл подключается только для чтения. После изменения конфигурации нужны
  перезапуск соответствующего процесса и проверка; горячего перечитывания нет.

Пример структуры, адреса .invalid намеренно нерабочие:
{
  "issuer": "https://auth.example.invalid/login",
  "authorization_endpoint": "https://auth.example.invalid/login/api/oidc/authorization",
  "token_endpoint": "https://auth.example.invalid/login/api/oidc/token",
  "jwks_uri": "https://auth.example.invalid/login/jwks.json",
  "client_id": "basework-test",
  "redirect_uri": "https://basework.example.invalid/auth/basework/oidc/callback",
  "secret_file": "/run/secrets/oidc_client_secret",
  "ca_file": null
}

Все восемь полей обязательны, лишние и повторяющиеся ключи запрещены.
issuer без завершающего /; discovery вычисляется как
issuer + /.well-known/openid-configuration.
Поддерживается закреплённая конфигурация провайдера: authorization/token/JWKS
на том же HTTPS origin и внутри пути issuer. Разные origins, query/fragment,
userinfo, неканонические пути и URL не поддерживаются. Точный callback имеет
путь /auth/basework/oidc/callback; адрес не берётся из Host/next запроса.
client_id: 1–100 букв ASCII, цифр или ._~-.

secret_file: отдельный файл в /run/secrets, имя из букв ASCII, цифр, _ или -.
Секрет — 32–4096 печатных ASCII-символов без пробелов внутри; конечный перевод
строки допускается. Не размещать значение в JSON, окружении браузера или Git.
ca_file=null: штатное доверие Requests, verify=True. Для собственного CA —
такой же ограниченный путь в /run/secrets; содержимое проверяется как PEM при
запуске. Неверный сертификат, имя сервера или неизвестный CA закрывают вход.
verify=False, proxy/CA из внешнего окружения и HTTP redirects не разрешаются
OIDC-транспортом. Публичный системный CA в этом локальном тесте не проверяется
успешным внешним запросом: сеть стенда не имеет внешнего выхода.

Ограничения безопасности
Запросы только GET discovery, GET JWKS и POST token по точным адресам.
Обмен выполняется вне SQL-транзакции, с прежними таймаутами и лимитом ответа.
Discovery обязан совпасть с конфигурацией и объявить code, S256, RS256,
client_secret_basic. Остальные поля, включая встроенные jwks и параметры
транспорта, не становятся настройками клиента. Подпись проверяется ключами
из закреплённого JWKS, проверку протокола выполняет Authlib.
Scope только openid, refresh/offline/userinfo не используются. Provider-токены
не сохраняются в прикладной сессии и не выдаются браузеру.
SESSION_COOKIE_SECURE и CSRF_COOKIE_SECURE включаются при OIDC даже для local.
ALLOWED_HOSTS, trusted proxy, CSRF origins и TLS gateway задаются отдельно
штатной конфигурацией публикации; этот файл не расширяет доверие к Host.
Общие EXTERNAL_READS/WRITES/REAL_MESSAGES/SCHEDULES остаются false: provider
разрешает лишь описанный транспорт, не снимая runtime guard, signer или RLS.

Все параметры, содержимое секрета и собственного CA участвуют в fingerprint
незавершённой попытки. После их смены попытку нужно начать заново. Изменение
системного trust store требует штатного перезапуска и повторной проверки.
Сохраняются одноразовые state/nonce/PKCE, явная iss+sub -> локальный UUID,
локальная MFA/step-up, серверный отзыв и отсутствие автопривязки по имени/email.
Смена режима/конфигурации не перепривязывает пользователей и не отзывает уже
выданные сессии автоматически. Для этого используются существующие операции
отзыва; снятие флага входа не заменяет блокировку доступа.

не используется как настоящая Authelia и не публикуется наружу.

Границы: локальный синтетический провайдер не подтверждает живое SSO Authelia,
браузерную приёмку или доставку блокировки из IdP за <=60 секунд. UI не менялся.
