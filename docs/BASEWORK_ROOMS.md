# Переговорки в BaseWork

Локальная реализация 31.10.2026. Публикация не выполнена. Существующие PostgreSQL-права и сессии BaseWork используются без новой миграции. Брони, владельцы и роли остаются в SQLite приложения `peregovorki`.

## Контракт

Браузер обращается только к своему backend:

- `GET /api/v1/basework/rooms/events?from=<ISO с зоной>&to=<ISO с зоной>` — не более 35 дней.
- `POST /api/v1/basework/rooms/events` — новая бронь или серия до 200 встреч.
- `PUT /api/v1/basework/rooms/events/<id>` — изменение, `expectedRevision`, область `one`, `following`, `all`.
- `DELETE /api/v1/basework/rooms/events/<id>` — отмена, те же версия и область в JSON.

Запись требует обычной полной зарегистрированной сессии, действующего `ApplicationAccess(rooms)`, CSRF и канонического UUID в `Idempotency-Key`. Автор берётся из сессии. Источник дополнительно проверяет явную привязку UUID BaseWork к прежнему идентификатору пользователя, активность, смену начального пароля, роль и владельца. Нет поиска соответствий по имени/почте и нет общей административной сессии.

Backend подписывает точное тело HMAC-SHA256 и отправляет его на `/api/basework`. Внешний метод всегда POST; внутренние методы ограничены списком выше. Подпись живёт 10 секунд. Нужны синхронные часы серверов. HTTP разрешён только для loopback в локальных проверках; для подключения стенда нужен HTTPS с обычной проверкой сертификата, без перенаправлений.

Чтение выполняется вне транзакции PostgreSQL; перед выдачей повторяется проверка того же пользователя/сессии. Запись удерживает прежние блокировки пользователя и сессии до ответа источника. Отзыв сериализуется с уже начавшейся записью; после фиксации отзыва старые запросы закрыты. HTTP: таймаут сокета 3 секунды, проверка общего времени между чтениями 5 секунд, ответ до 2 MiB. Это не абсолютный пятисекундный дедлайн: завершающее блокирующее чтение может добавить до 3 секунд. Браузер ждёт 8 секунд и при неопределённости сохраняет прежний запрос.

В источнике бронь и квитанция идемпотентности коммитятся одной SQLite-транзакцией. Повтор с тем же ключом и телом возвращает прежний ответ; изменение тела или состояния профиля отклоняется. Квитанции не удаляются автоматически. После потери ответа нельзя создавать новый ключ. Ключ и тело неподтверждённой операции сохраняются только в памяти текущей вкладки, отдельно для каждого UUID. Полная перезагрузка/закрытие уничтожает эту память: сначала сверить календарь, не повторять создание вслепую. При обычной перезагрузке открытого календаря с неподтверждённой записью показывается предупреждение браузера.

`revision` учитывает всю серию: изменение любого её элемента делает прежнюю версию устаревшей. Это намеренно консервативная защита от потери изменений.

## Настройки

По умолчанию адаптер не подключён, запись выключена. Переменные только у `web`:

- `BASEWORK_ROOMS_URL` — проверенный HTTPS URL, путь строго `/api/basework`.
- `BASEWORK_ROOMS_KEY_FILE` — файл с ровно 32 случайными байтами; не строка hex/base64.
- `BASEWORK_ROOMS_WRITES=1` — отдельное включение записи после чтения и приёмки.

`beta/deploy/compose.rooms.json` — необязательный фрагмент для согласованного compose. Его нельзя использовать вместо полного compose стенда. `BASEWORK_ROOMS_SECRET_FILE` задаёт существующий закрытый файл на хосте. Ключ не включать в Git, образы, frontend, журналы, URL и ответы. Не передавать его сторонним сервисам.

У источника — `BASEWORK_BRIDGE_KEY_FILE` с теми же 32 байтами и `BASEWORK_BRIDGE_BINDINGS_FILE` с объектом `{"bindings":{}}`. Пустой объект никому не даёт доступа. Только после отдельного согласования добавлять проверенные пары UUID → прежний 32-символьный id. Один прежний профиль нельзя связать с несколькими UUID. `ApplicationAccess` и привязка — разные необходимые условия.

В `peregovorki/rooms.service` добавлен необязательный `/etc/peregovorki/basework.env`; образец находится в `deploy/basework.env.example`. Сам файл настроек и секреты не создавались на сервере. Включение bridge создаёт только дополнительную таблицу `basework_receipts` в прежней SQLite. Старые таблицы и UUID не пересоздаются. Рабочее окно для записей из BaseWork: Москва, Пн–Пт 08:00–19:00, включая всю переносимую серию. Производственный календарь праздников не подключён. Старый UI сохраняет прежние правила.
